# 高速服务区智能盘点软件 V13 Complete

面向 Windows 本地使用的中文盘点软件。上传两份初盘报表后直接复盘，按品类生成 A4 复盘单，并在本地保存批次、修改轨迹与打印历史。

本仓库只包含程序源码和从零生成的虚构测试样本。默认供应商目录为空；不包含公司真实报表、供应商数据库、盘点记录、SQLite 文件、打印历史或凭证。GitHub 用于管理源码；实际业务数据始终由使用者保存在电脑本地。

## Windows 启动

1. 安装 Python 3.11～3.13 的 64 位版本，并安装 Windows 黑体 `simhei.ttf`。
2. 下载或克隆本仓库到独立目录，双击 `启动完整盘点客户端.cmd`。
3. 首次启动会在该目录创建 `.venv` 并安装锁定依赖，需要联网。安装完成后，日常盘点与保存不依赖云服务器。
4. 浏览器打开 `http://127.0.0.1:8513/`，使用期间保留启动窗口。

如果同一电脑已有正式客户端运行，请使用独立目录与端口，不要覆盖正式软件或把正式数据复制到仓库：

```powershell
$env:STOCKTAKE_PORT='8514'
$env:STOCKTAKE_DATA_DIR=Join-Path $env:LOCALAPPDATA 'StocktakeSandbox'
.\启动完整盘点客户端.cmd
```

默认数据库在程序目录的 `data/` 下首次生成。该目录及导入、导出文件均被 Git 忽略。`STOCKTAKE_CJK_FONT` 可指定另一份可嵌入的 TrueType 中文字体路径；字体文件不随源码分发。

## 主要操作

- **01复盘与智能找差异**：上传盘盈与盘亏 `.xls/.xlsx`，无需手填店名或期间。六列显示商品、最新差异、实数、备注和简短线索；商品名称自动换行，普通页面滚动。顶部可直接输入实际销售额和同期含税销售成本，实时查看两位小数的净差异率、2‰额度及当前测算状态。两个经营值按批次自动保存。
- **智能找差异**：主行只显示“疑似串码N项 / A换B N项”等数量，点击查看前3条和双方成本、条码、差异、匹配原因、来源依据与轨迹，可继续展开并定位。常用搜索、品类、撤销和批量粘贴直接可用，其余组合筛选、排序和刷新折叠到“更多筛选”。空白表示未复盘，0是有效实数；输入会自动保存，亦可Enter或离开单元格保存。
- **02变化/导出**：查看找回、盘盈变化与最新总数，导出带草稿提示的七表工作簿。展开“正式导出检查”处理完整性、错误和凭证，校验通过后生成严格三列的公司候选文件：`商品编码、商品条码、数量`，数量是最新实物总数。没有独立03页面；所有原有导出阻断保留。
- **生成盘点汇报**：01右上按钮打开汇报窗口，可修改日期、统计期间、季度和经店长确认的原因；全部金额读取当前批次，正数写盘盈、负数写盘亏、零值写差异。可编辑最终稿并一键复制。独立鲜食数据可选，未提供不显示，也不叠加普通盘点。数据变化后生成新稿，过期的人工稿保留为对照。
- **供货商数据库**：本地导入自有目录，多条码、列映射、重复供应商冲突与选主。不会向 GitHub 同步。
- **打印历史**：按品类预览并生成 A4，默认选择未填实数且最新差异不为 0 的商品。原单重印沿用原 PDF；按当前数据生成新单另建打印记录。
- **高级异常明细**：商品档案、成对候选、跨店与交易证据、参数和逐商品修改轨迹。证据不会自动修正库存。

疑似串码候选要求不同条码、最新差异反向且非零、成本按分四舍五入相同，并且部类/大类/中类任一相同。可显式启用 0.01 成本容差；售价只作为排序证据。差异归零撤销相关候选，再次有差异则重新计算，人工备注保留。相同供应商的 A换B 另行分析。

当前差异 = 最新实物总数 − 系统数 + 原始调整。逐行差异成本按分四舍五入，报损率 = 盘盈盘亏净合计 ÷ 同期含税销售成本 × 1000；净损耗率结合 2‰ 标准提示审核。软件不自动修改公司库存、不自动对冲商品、不自动提交审批。

## 模拟演示与测试

安装开发依赖并运行测试：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest tests -q
```

也可双击 `run_tests.bat`。测试通过临时目录建立模拟 SQLite，关闭后不会影响正式软件。测试覆盖数量/金额、0与空白、候选撤销及恢复、供应商冲突、严格三列、2‰精确边界、2万条计数、版本冲突、撤销、备份恢复、PDF原单重印、五个界面入口、经营值隔离、旧库兼容和汇报正负零/独立鲜食。完整验收见 [ACCEPTANCE.md](ACCEPTANCE.md)。

生成可以手动上传的**虚构**报表（输出目录不纳入 Git）：

```powershell
.venv\Scripts\python.exe tests/synthetic_data.py --output tests/runtime/simulated
```

公开测试通过独立手算模拟输入验证行为，不包含内部真实报表、原母版或 WPS 的业务缓存，也不声称替代内部真实文件验收。Windows需要可用中文字体；Linux CI使用系统安装的文泉驿字体。实际浏览器测试见 `tests/browser_optimization.mjs`（三种分辨率、经营输入、汇报与复制）、`tests/browser_existing_modules.mjs`（打印、供应商、跨店、连续输入、正式三列下载）和 `tests/browser_synthetic.mjs`。仅在独立 `STOCKTAKE_DATA_DIR` 和端口运行，使用Playwright及Edge；先生成模拟样本，并运行 `tests/prepare_module_demo.py` 生成可选证据。

## 源码管理

`main` 是稳定源码。重大修改从 `main` 新建 `feature/…` 或 `fix/…` 分支，通过 Pull Request 描述问题、行为变化和验证结果，再审查合并；详见 [CONTRIBUTING.md](CONTRIBUTING.md)。GitHub Actions 对每次推送和 PR 运行模拟测试与发布隐私检查。

提交前运行：

```powershell
git add <本次修改的源码路径>
python scripts/check_public_tree.py
```

该检查会审查暂存区和全部可达 Git 历史，阻止业务文件、数据库、凭证、非文本和大文件。检查不能替代人工审阅；不要用 `git add -f` 绕过忽略规则，也不要把真实数据粘贴到代码、Issue、PR、截图或测试断言中。

## 文件结构

|路径|用途|
|---|---|
|`app.py`、`client_app.py`|中文客户端与五个操作入口|
|`core.py`、`source_core.py`|数量金额计算、报表解析和导出门槛|
|`intelligence.py`|候选索引、风险与找差异模型|
|`reporting.py`|经营测算、精确格式、季度文字和独立鲜食|
|`storage.py`|SQLite、原件、轨迹、幂等、版本与备份|
|`imports_exports.py`|工作簿、供应商及证据的导入导出|
|`print_manager.py`、`pdf_renderer.py`|打印范围、PDF及原单重印|
|`workbench_component.py`、`ui/`|交互复盘工作台|
|`bootstrap.py`、Windows脚本|环境准备和本地启动|
|`requirements*.txt`|运行及测试依赖|
|`tests/`|模拟生成器、业务回归、界面和浏览器测试|
|`scripts/check_public_tree.py`|暂存区及全部历史的公开发布检查|
|`SOURCE_MANIFEST.json`|首次发布的完整文件清单及SHA256|

## 本地数据与备份

使用界面中的备份/审计包功能保存本地副本，备份文件放在源码仓库之外。升级前先备份，测试通过后再部署到正式环境；不应直接拉取开发分支覆盖正在营业的客户端。本仓库不附带原电脑路径、历史业务报告或安装环境。

旧数据库无需重建：销售额与汇报配置在已有批次meta中兼容补默认值，首次读取不写回旧记录。安全更新应先在独立端口和模拟目录验收，再停止正式进程、用SQLite备份API获取包含WAL提交内容的一致性副本，只替换本次PR涉及的运行源码及前端文件。保留 `data/`、实际供应商文件、虚拟环境及历史打印；启动后逐表比对业务行并确认原端口健康。回滚时先关程序、备份当前状态，再恢复更新前程序与一致性数据库，不能在运行中直接拷贝数据库主文件。
