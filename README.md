# 高速服务区智能盘点软件 V13 Complete

面向 Windows 本地使用的中文盘点软件。上传两份初盘报表后直接复盘，按品类生成 A4 复盘单，并在本地保存批次、修改轨迹与打印历史。

本仓库只包含程序源码和从零生成的虚构测试样本。默认供应商目录为空；不包含公司真实报表、供应商数据库、盘点记录、SQLite 文件、打印历史或凭证。GitHub 用于管理源码；实际业务数据始终由使用者保存在电脑本地。

## Windows 启动

1. 安装 Python 3.11～3.13 的 64 位版本，并安装 Windows 黑体 `simhei.ttf`。
2. 下载或克隆本仓库到独立目录，双击 `启动完整盘点客户端.cmd`。
3. 首次启动会在该目录创建 `.venv` 并安装锁定依赖，需要联网。安装完成后，日常盘点与保存不依赖云服务器。
4. 浏览器打开 `http://127.0.0.1:8513/`，使用期间保留启动窗口。

如果同一电脑已有正式客户端运行，请使用独立目录与端口，不要覆盖正式软件或把正式数据复制到仓库：

```powershell
$env:STOCKTAKE_PORT='8514'
$env:STOCKTAKE_DATA_DIR=Join-Path $env:LOCALAPPDATA 'StocktakeSandbox'
.\启动完整盘点客户端.cmd
```

默认数据库在程序目录的 `data/` 下首次生成。该目录及导入、导出文件均被 Git 忽略。`STOCKTAKE_CJK_FONT` 可指定另一份可嵌入的 TrueType 中文字体路径；字体文件不随源码分发。

## 主要操作

上传盘盈、盘亏两张初盘报表后直接进入01，不再要求补填店名和日期。

- **01 连续复盘找差异**：正常页面滚轮连续浏览全部商品，无上一页、下一页。主行直接显示系统数、初盘数、复盘实数、初盘→最新差异、找回/增加/归零变化、差异成本、备注。空白表示未复盘，0是有效实数。输入自动保存，也可Enter或离开单元格保存；保存与详情开关保留位置和焦点。
- **具体对应商品**：主行直接显示疑似串码或A换B的商品名、完整条码和对方差异。默认将最合适的两条真实商品就近联排，两条都可直接填写；更多对应商品进入详情完整查看，不重复计数。可切换按差异金额找货；保存时保留当前位置，点击“重新联排/刷新排序”按最新线索重排。归零撤销相关候选、恢复后重新识别，人工备注始终独立。
- **02 公司盘点结果导出**：只提供当前批次、商品/待复盘数、数据检查、三列预览和公司`.xls`下载。所有原有完整性、条码/编码、单位、凭证及2‰审核门槛保留，在同一折叠检查区处理。未完成为核对草稿；通过本机检查才可下载正式候选，审批和系统上传仍由人工完成。
- **公司模板**：真正的旧格式`.xls`，唯一工作表`Sheet1`，严格三列`商品编码、商品条码、数量`；前两列文本、第三列数值，前导零和0保留，每行对应01最新保存的有效实物总数。绝不混用五列补货申请单。
- **03 现场复核单打印**：默认未填复盘实数且差异非零，盘亏优先，同时保留盘盈。选择品类和待复盘/当前盘亏/全部差异，直接预览A4或生成保存PDF。大尺寸空框填写现场实数、醒目名称及简短对应商品提示，成对商品尽量相邻同页。历史记录折叠，原单重印使用相同PDF字节，按新数据打印另建记录。没有独立核查状态字段。
- **经营测算与盘点汇报**：01顶部销售额、同期含税销售成本、净差异率、2‰额度紧凑显示。汇报可编辑、保存和复制，可选独立鲜食。打开、按最新数据重新生成及复制均等当前输入保存并核对最新版本；失败、冲突、取消不会误报已复制。源数据变化后的过期人工稿只作对照。
- **更多工具**：保留供应商导入/冲突选主、商品档案、候选与跨店/交易证据、轨迹、参数、变化清单、七表母版、原始来源和本地备份。

疑似串码仍要求不同条码、最新差异反向且非零、按既定精度成本相同，并且部类/大类/中类任一相同。可显式启用既有0.01成本容差；规格、品牌、数量和售价只作排序/证据。A换B使用既有供应商规则，疑似不代表已确认。

初盘差异＝初盘数−系统数＋原始调整；复盘留空沿用初盘，填写后使用复盘实数；最新差异＝有效实物总数−系统数＋原始调整。合法原始单位换算调整保留，逐行成本按分四舍五入。报损率＝盘盈盘亏净合计÷同期含税销售成本×1000，结合完整性和2‰标准提示审核。软件不自动修改公司库存、不自动抵销商品、不自动提交审批。

## 模拟演示与测试

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest tests -q
```

也可双击`run_tests.bat`。82项自动测试覆盖原有全部回归及连续录入、V13原始调整、候选动态撤销、450条严格三列、现场单范围、合并输入撤销与汇报签名。测试只在临时模拟库运行。公开仓库不含内部母版及真实经营缓存，模拟回归不冒充真实文件验收。

实际Edge浏览器验收和重启流程见[ACCEPTANCE.md](ACCEPTANCE.md)。生成450条虚构上传文件：

```powershell
.venv\Scripts\python.exe tests/prepare_workflow_demo.py
```

在独立`STOCKTAKE_DATA_DIR`和18541端口启动，安装Playwright及Edge后依次运行：`tests/browser_workflow.mjs`、`tests/browser_report_barrier.mjs`，独立读回`tests/verify_workflow_artifacts.py`。真正重启测试进程前后运行其`before/after`模式和`tests/browser_workflow_reopen.mjs`。供应商及跨店界面补充回归用`tests/browser_existing_modules.mjs`，独立18542端口与12条模拟批次。所有生成文件与截图留在忽略目录`tests/runtime/`；只提交无业务记录的`tests/workflow_acceptance.json`。

## 源码管理

`main` 是稳定源码。重大修改从 `main` 新建 `feature/…` 或 `fix/…` 分支，通过 Pull Request 描述问题、行为变化和验证结果，再审查合并；详见 [CONTRIBUTING.md](CONTRIBUTING.md)。GitHub Actions 对每次推送和 PR 运行模拟测试与发布隐私检查。

提交前运行：

```powershell
git add <本次修改的源码路径>
python scripts/check_public_tree.py
```

该检查会审查暂存区和全部可达 Git 历史，阻止业务文件、数据库、凭证、非文本和大文件。检查不能替代人工审阅；不要用 `git add -f` 绕过忽略规则，也不要把真实数据粘贴到代码、Issue、PR、截图或测试断言中。

## 本地数据与备份

使用界面中的备份/审计包功能保存本地副本，备份文件放在源码仓库之外。升级前先备份，测试通过后再部署到正式环境；不应直接拉取开发分支覆盖正在营业的客户端。本仓库不附带原电脑路径、历史业务报告或安装环境。

旧数据库无需重建：销售额与汇报配置在已有批次meta中兼容补默认值，首次读取不写回旧记录。安全更新应先在独立端口和模拟目录验收，再停止正式进程、用SQLite备份API获取包含WAL提交内容的一致性副本，只替换本次PR涉及的运行源码及前端文件。保留 `data/`、实际供应商文件、虚拟环境及历史打印；启动后逐表比对业务行并确认原端口健康。回滚时先关程序、备份当前状态，再恢复更新前程序与一致性数据库，不能在运行中直接拷贝数据库主文件。
