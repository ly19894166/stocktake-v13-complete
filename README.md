# 高速服务区智能盘点软件 V13 Complete

面向 Windows 本地使用的中文盘点软件。上传两份初盘报表后直接复盘，按品类生成 A4 复盘单，并在本地保存批次、修改轨迹与打印历史。

本仓库只包含程序源码和从零生成的虚构测试样本。默认供应商目录为空；不包含公司真实报表、供应商数据库、盘点记录、SQLite 文件、打印历史或凭证。GitHub 用于管理源码；实际业务数据始终由使用者保存在电脑本地。

## Windows 启动

1. 安装 Python 3.11～3.13 的 64 位版本，并安装 Windows 黑体 `simhei.ttf`。
2. 下载或克隆本仓库到独立目录，双击 `启动完整盘点客户端.cmd`。
3. 首次启动会在该目录创建 `.venv` 并安装锁定依赖，需要联网。安装完成后，日常盘点与保存不依赖云服务器。
4. 浏览器打开 `http://127.0.0.1:8513/`，使用期间保留启动窗口。

如果同一电脑已有正式客户端运行，请使用独立目录与端口，不要覆盖正式软件或把正式数据复制到仓库：

```powershell
$env:STOCKTAKE_PORT='8514'
$env:STOCKTAKE_DATA_DIR=Join-Path $env:LOCALAPPDATA 'StocktakeSandbox'
.\启动完整盘点客户端.cmd
```

默认数据库在程序目录的 `data/` 下首次生成。该目录及导入、导出文件均被 Git 忽略。`STOCKTAKE_CJK_FONT` 可指定另一份可嵌入的 TrueType 中文字体路径；字体文件不随源码分发。

## 主要操作

- **上传盘点报表**：首页唯一主入口，一个多文件控件同时选择盘盈和盘亏两份原始`.xls/.xlsx`，顺序不限。校验实际数量方向、结构和文件标识，两类完整且可唯一识别才导入；重复上传恢复已有复盘，不生成覆盖批次。无需填写店名、时间或操作人。旧批次、操作人和完整V13导入统一收在“历史批次与高级设置”。
- **01连续复盘**：保留母版逻辑并新增差异金额，共14列横向对照、原始序号默认、普通38px行和30px黄色实数框，备注单行可展开。1920/2560优先显示14列，1366折叠编码与供应商，核心输入和差异金额始终可见，不横向滚动。空白代表未复盘，0代表已确认实物为0。自动保存、批量粘贴、撤销、搜索、金额/联排/品类排序及归零撤销线索均保留。
- **悬浮七项统计**：销售额、同期含税成本及汇报入口在正常顶部；七项盘盈/盘亏/净差异/净差异率/2‰额度/剩余或超标/已填剩余单独悬浮，滚动到第200/400条仍可见。固定表头位于其下方，不遮挡输入。金额来自完整盘点，打印排除卓不凡不改变测算。
- **01下载盘点结果 ▾**：悬浮窗口显示全店批次、复盘进度、完整性核查、剩余问题及三列预览。每次预览/下载先提交未保存实数和经营草稿，等保存确认后重新读全批次最新版本。保留原正式阻断，真`.xls`仅`商品编码、商品条码、数量`三列，文本/文本/数值；不受01筛选影响。关闭弹窗恢复商品焦点与滚动位置。导航不再有02。
- **01表头筛选**：商品范围默认“不含卓不凡”，可选全部、仅卓不凡。待确认不会静默删除。表头组合数量、金额、品类、备注、串码/卓不凡资格、供应商和完整条码/尾号等条件。清除筛选恢复默认范围与原序号，不删草稿。范围盘盈/盘亏/净差异小计使用原始十进制值，明确区别于顶部整店统计。
- **01选中计数与求和**：鼠标拖选数值格、Shift矩形、Ctrl追加，固定底栏显示选中格数、数值计数和求和。使用后端未格式化十进制字符串及BigInt运算；负数、0参与，空白不计。金额与各计量单位分别求和，不把件数和元相加。
- **01卓不凡A换B专项核对**：仅确认属于卓不凡、同有效供应商范围的商品有资格。普通商品即使曾人工启用，仍无资格；普通疑似串码独立保留。旧人工档案与修改历史在更多工具只读追溯，不能新增有效授权。独立16列专项Excel、旧人工说明与凭证仍保留。
- **卓不凡数量建议**：选择仅卓不凡即自动分析，建议独立于正式实盘。只对同供应商、相同可靠计量口径、关系唯一且方向相反的两件未复盘商品生成；单位/包装不清、多候选争抢、冲突等只列原因。原始调整继续交给V13内核。可修改建议、保存独立草稿、驳回或逐条确认。只有确认本条实盘才改正式实数；单方确认重算另一端，双方均确认且数量守恒才核实关系。剩余差异和不同成本分别保留。详见[建议账本与迁移说明](EXCHANGE_DATABASE.md)。
- **03现场复核单**：默认未填实数且差异非零，并排除已确认卓不凡；待确认商品默认保留且显示数量。可选“包含卓不凡商品”“仅打印卓不凡”“打印供货商待确认商品”。预览、留档和历史范围按最新数据创建新单使用同一筛选函数；历史原单重印始终复用保存时PDF字节。
- **省纸A4**：横向8列：序号、品类、商品名称、完整条码、系统数、初盘数、最新差异、现场实数。常规17条/页，中文字体嵌入、22点高手写框、长名称完整换行。纸单没有串码/A换B文字、关联背景或配对排序；智能分析在01处理。
- **找货顺序**：03默认按实际大类、中类、原始序号稳定排序，也可选原始序号或金额优先。可从档案已有品类选择并确认现场路线；未提供时不推测货架位置。
- **更多工具**：供应商数据库、编码/冲突归属确认、商品档案、异常、跨店证据、参数、轨迹、变化清单、七表母版及备份保留。季度汇报仍可编辑、保存、复制，保留最新保存屏障和可选独立鲜食。

## 供应商归属与本地资料

`supplier_policy.py`为01筛选与审计、03打印提供同一归属。读取本机`vendors.json`和已保存批次目录，以完整条码、有效期及唯一供应商编码为依据；有效期使用批次首次导入日期（可显式绑定supplier_as_of），不随系统当前日期漂移。名称“桌不凡”只在对应已确认卓不凡编码时用于归一化识别；无编码时，仅允许完整条码唯一且名称准确为“卓不凡”的本机目录记录按标准名称确认，编码仍留空；未匹配、有效期不明、未核实别名或多供应商冲突标为“供货商待确认”。目录显示名称统一为卓不凡，归属判定另行显示；原始资料仍留档。

需要时在更多工具中，按本机目录已有编码保存人工确认；同条码冲突可单独选择有效编码或保留待确认。确认写入当前批次meta并留痕，不硬编码真实供应商编码或商品名单。公开`vendors.json`始终为空，真实目录不随Git上传。

V13数量、原始调整、逐行成本四舍五入和审核标准不变。净差异＝盘盈＋盘亏；净差异率＝净差异÷同期含税销售成本×1000‰；净损耗＝MAX(0,−净差异)，额度＝成本×0.002。按未舍入金额比较，界面显示两位小数；未完成只作当前测算，不代表最终通过。软件不自动改公司库存、不自动审批。

## 源码管理

`main` 是稳定源码。重大修改从 `main` 新建 `feature/…` 或 `fix/…` 分支，通过 Pull Request 描述问题、行为变化和验证结果，再审查合并；详见 [CONTRIBUTING.md](CONTRIBUTING.md)。GitHub Actions 对每次推送和 PR 运行模拟测试与发布隐私检查。

提交前运行：

```powershell
git add <本次修改的源码路径>
python scripts/check_public_tree.py
```

该检查会审查暂存区和全部可达 Git 历史，阻止业务文件、数据库、凭证、非文本和大文件。检查不能替代人工审阅；不要用 `git add -f` 绕过忽略规则，也不要把真实数据粘贴到代码、Issue、PR、截图或测试断言中。

## 本地数据与备份

使用界面中的备份/审计包功能保存本地副本，备份文件放在源码仓库之外。升级前先备份，测试通过后再部署到正式环境；不应直接拉取开发分支覆盖正在营业的客户端。本仓库不附带原电脑路径、历史业务报告或安装环境。

旧数据库无需重建：安全新增exchange_products、exchange_history两表并将结构版本从14升为15，原8张业务表不改写；销售额与汇报配置在已有批次meta中兼容补默认值，首次读取不写回旧记录。安全更新应先在独立端口和模拟目录验收，再停止正式进程、用SQLite备份API获取包含WAL提交内容的一致性副本，只替换本次PR涉及的运行源码及前端文件。保留 `data/`、实际供应商文件、虚拟环境及历史打印；启动后逐表比对业务行并确认原端口健康。回滚时先关程序、备份当前状态，优先只恢复更新前程序，保留数据和新增档案表；只有明确需要撤销业务录入时才评估旧库恢复，不能在运行中覆盖主文件或丢弃升级后的新记录。
